# blueprint4llm

**Языки:** [English](README.md) | [Русский](README.ru.md) | [Español](README.es.md) | [中文](README.zh.md) | [हिन्दी](README.hi.md) | [Français](README.fr.md) | [العربية](README.ar.md)

**Планы в Markdown → диаграммы, прототипы интерфейсов, графики, HTML и PDF.**

Составьте план самостоятельно или с помощью агента. Перед реализацией изучите систему и экраны.
Markdown остаётся источником истины; CLI преобразует его без вызова LLM.

![Исходный файл Markdown рядом с отрисованной диаграммой Mermaid, экраном Balsamiq и графиком статусов запросов](https://raw.githubusercontent.com/evgenyigumnov/blueprint4llm/main/docs/assets/markdown-to-visual.png)

## Пример

## Быстрый старт

### Использование с Codex или Claude Code

В каталоге проекта установите навык `blueprint4llm` с помощью [skills CLI](https://github.com/vercel-labs/skills):

```bash
# Codex
npx skills add evgenyigumnov/blueprint4llm --skill blueprint4llm --agent codex

# Claude Code
npx skills add evgenyigumnov/blueprint4llm --skill blueprint4llm --agent claude-code
```

Для установки нужны **Node.js ≥22.20.0** и npm. По умолчанию навык устанавливается для текущего проекта; добавьте `--global`, чтобы использовать его во всех проектах. Codex хранит навыки проекта в `.agents/skills/`, а Claude Code — в `.claude/skills/`.

Вызовите навык в своём агенте:

```text
# Codex
$blueprint4llm Создай визуальный план для очереди задач.

# Claude Code
/blueprint4llm Создай визуальный план для очереди задач.
```

Навык помогает агенту составить визуальный план, проверить и отрисовать его, а затем просмотреть каждую визуализацию. Для отрисовки нужны CLI `blueprint4llm` и Chrome от Puppeteer; установка и запуск CLI описаны в следующем разделе.

### Использование CLI напрямую

Нужны **Node.js ≥22.13.0**, npm и Chrome от Puppeteer.

```bash
npm install --global blueprint4llm
```

Сохраните этот текст в `plan.md`:

````markdown
# Процесс обработки запроса

```d2
form: Форма запроса
api: Проверка API
queue: Очередь обработки

form -> api
api -> queue
```
````

```bash
blueprint4llm plan.md --serve
```

Откройте напечатанный URL, обычно `http://127.0.0.1:8080/`. При сохранении Markdown или указанного локального изображения предпросмотр обновляется. На панели инструментов доступны тёмный режим и загрузка PDF. Остановите сервер сочетанием `Ctrl+C`.

Обычно Chrome устанавливается автоматически. Если скрипты установки были заблокированы, установите браузер вручную:

```bash
npm exec --yes --package=puppeteer@25.14.0 -- puppeteer browsers install chrome
```

### Кадры Figma

Для режима JSON нужен корневой элемент `DOCUMENT`; токен и подключение к сети не требуются. Выберите кадр с помощью `node=12:34` в метаданных блока. Локальный отрисовщик поддерживает контейнеры, простые фигуры, векторные контуры, текст и сплошную заливку; для градиентов, эффектов, масок и изображений используйте режим URL.

В режиме URL принимаются HTTPS-ссылки на кадры `/design/` или `/file/`. Используйте персональный токен доступа с разрешением `file_content:read`. Токен ищется в следующем порядке: `CompileOptions.figmaAccessToken`, `FIGMA_ACCESS_TOKEN`, затем `.env` в текущем рабочем каталоге. Токен отправляется только на `api.figma.com`; экспортированные SVG встраиваются в результат.

## Команды

| Задача                          | Команда                                                                |
| ------------------------------- | ---------------------------------------------------------------------- |
| Предпросмотр в реальном времени | `blueprint4llm plan.md --serve --port=8080`                            |
| Проверка для CI                 | `blueprint4llm plan.md --check`                                        |
| Проверка с отчётом              | `blueprint4llm plan.md --check --report-json=diagnostics.json`         |
| Экспорт с отчётом               | `blueprint4llm plan.md --out=plan.html --report-json=diagnostics.json` |
| Экспорт HTML                    | `blueprint4llm plan.md --out=plan.html`                                |
| Экспорт со сводкой              | `blueprint4llm plan.md --out=plan.html --diagnostics-summary`          |
| Экспорт PDF                     | `blueprint4llm plan.md --out=plan.pdf --format=pdf`                    |
| Экспорт SVG                     | `blueprint4llm plan.md --out=visual.svg --format=svg`                  |
| Экспорт PNG                     | `blueprint4llm plan.md --out=visual.png --format=png`                  |
| Экспорт JPEG                    | `blueprint4llm plan.md --out=visual.jpeg --format=jpeg`                |

Для экспорта изображений нужен **ровно один поддерживаемый визуальный блок**; пример из быстрого старта подходит. Параметр `--out` создаёт родительские каталоги. Каждый запуск создаёт один формат; по умолчанию используется HTML. `--check` проверяет Markdown, диаграммы и локальные изображения, не записывая HTML или ресурсы. Необязательный `--report-json=<file>` атомарно записывает JSON-отчёт в UTF-8. Он работает с `--check` и разовыми экспортами. Путь отчёта должен отличаться от путей входного и выходного файлов, включая символьные ссылки. `--report-json` нельзя использовать с `--serve`.

По умолчанию в созданных документах не отображается общее число ошибок и предупреждений. Добавьте `--diagnostics-summary` к экспорту HTML или PDF либо к предпросмотру, чтобы включить его. Ошибка диаграммы отображается полностью на её месте; остальной Markdown и корректные диаграммы остаются доступными. Экспорт HTML и PDF сохраняется даже при ошибке диаграммы, после чего команда завершается с кодом `1`. Экспорт SVG, PNG и JPEG не заменяет существующий файл, если в диаграмме есть ошибка. Если есть только предупреждения, код завершения — `0`. Недопустимые аргументы, включая конфликт путей отчёта, приводят к коду `2`.

Отчёт содержит `schemaVersion: 1`, значение `status` (`ok` или `error`), сводные счётчики и упорядоченные диагностические записи. Каждая запись включает `severity`, стабильный `code`, `scope`, путь к исходному файлу, необязательные координаты Markdown и идентификатор диаграммы, а также полное сообщение. Коды: `diagram.render`, `diagram.limit`, `diagram.svg`, `renderer.warning`, `document.read`, `document.compile`, `output.render` и `output.write`. Необязательный объект `outputs` перечисляет файлы, сохранённые этим запуском. Например, отчёты `--check` не содержат поля `outputs`.

Критические ошибки документа или экспорта прерывают эту операцию. Если запрошен JSON-отчёт и его ещё можно записать, в нём будет диагностика документа или вывода. Если записать отчёт не удаётся, сообщение выводится в stderr, а команда завершается с кодом `1`; ранее сохранённые HTML- или PDF-файлы остаются доступными. Пример документа с двумя независимыми ошибками диаграмм и корректной диаграммой между ними приведён в [`examples/blueprint-diagnostics.md`](examples/blueprint-diagnostics.md).

В режиме предпросмотра ошибки диаграмм остаются встроенными в документ, а PDF использует тот же скомпилированный документ. Общее число ошибок отображается только при включённом `--diagnostics-summary`. После исправления исходника диагностика исчезает при следующей сборке. Критическая ошибка документа отображается на отдельной странице до исправления исходника.

## Программный API

Установите пакет локально командой `npm install blueprint4llm`, затем используйте экспорты ESM:

```js
import { compileMarkdown, writeBlueprintOutput } from 'blueprint4llm';

const compiled = await compileMarkdown('# Plan\n\nReady for review.', {
  sourceFile: './plan.md',
  includeDiagnosticsSummary: true,
});

await writeBlueprintOutput('./plan.html', {
  html: compiled.html,
  assets: compiled.assets,
});
```

| Экспорт                                       | Назначение                                                                                                            |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `compileMarkdown(markdown, options)`          | Возвращает `html`, `title`, `assets`, устаревшие массивы строк `warnings`/`errors` и структурированные `diagnostics`. |
| `renderPdf(compiled, { signal }?)`            | Создаёт байты PDF; передайте их в `writeBlueprintOutput()` как `pdf`.                                                 |
| `writeBlueprintOutput(path, options)`         | Записывает HTML и/или PDF с ресурсами и возвращает абсолютные пути к файлам.                                          |
| `startPreviewServer({ input, port, signal })` | Возвращает `url`, `port` и асинхронный метод `close()`.                                                               |

`warnings` и `errors` остаются форматированными массивами строк для существующих потребителей. `diagnostics` добавляет структурированные записи; в публичных типах поле необязательно, чтобы старые реализации компилятора могли возвращать только массивы строк. Встроенный компилятор всегда возвращает `diagnostics`. Установите `includeDiagnosticsSummary: true` в `CompileOptions`, чтобы добавить доступную сводку в создаваемый HTML. По умолчанию она отключена. `startPreviewServer()` принимает тот же параметр.
