# План развития blueprint4llm

Ближайшая очередь: **2 функции и 3 формата**. Все задачи открыты. Порядок внутри каждого списка задаёт приоритет; ID сохранены из прежнего плана.

## Для чего развиваем инструмент

Программист согласует цель, ограничения и критерии приёмки, затем оценивает результат и прохождение тестов. В детали исходника он погружается, когда возникает проблема. План должен помогать принимать эти решения без постоянного контроля действий агента.

В начале документа достаточно видеть цель, ограничения, ожидаемое поведение и результат тестов со ссылкой на отчёт запуска. Схемы и макеты объясняют устройство системы и пользовательский сценарий на нужном уровне.

`--check` проверяет Markdown, схемы и ресурсы документа. Результаты тестов приложения берутся из его тестового запуска и добавляются в план как обычный Markdown.

Основа текущего состояния: [README](README.md), исходный код, тесты и [расширение VS Code](vscode-extension/README.md).

### FEAT-05: поведение при ошибках диаграмм

- Ошибка любой отдельной диаграммы не прерывает обработку Markdown: весь текст и остальные схемы рендерятся в исходном порядке.
- На месте каждого сбойного блока виден подробный текст ошибки с файлом и строкой. Многострочные и длинные сообщения сохраняют читаемость.
- Одноразовая команда экспорта сохраняет HTML/PDF со всеми доступными блоками и сообщениями об ошибках, затем возвращает код `1`. Все ошибки также выводятся в stderr. Если ошибок нет, код завершения — `0`.
- `--check` собирает ошибки всех независимых блоков за один запуск, выводит их в stderr и возвращает код `1`, не создавая документ.
- Preview в браузере и VS Code показывает текущий документ с ошибками на местах схем и обновляется после исправления.

Критерий приёмки: документ с двумя сломанными схемами, одной исправной и текстом до, между и после блоков целиком доступен в HTML/PDF и preview. Обе ошибки видны на своих местах; одноразовый CLI сохраняет результат, сообщает обе ошибки в stderr и завершается с кодом `1`.

## Что убрали из ближайшей очереди

Для планов используем один Markdown-файл, для отправки результата — существующий экспорт в PDF.

Синхронную прокрутку с исходником, сравнение ревизий схем, пакетный экспорт, расширенные настройки PDF, кликабельные прототипы, систему конфигов и шаблонов. Они добавляют отдельные сценарии, которые пока не нужны для согласования плана и приёмки результата.

Остальные семь форматов отложены: существующих средств достаточно для основных схем и макетов. Возвращаем задачу в очередь, когда конкретный рабочий сценарий упирается в это ограничение.

## Когда задача готова

- Пользовательский сценарий работает, границы поддержки и ограничения описаны в README и примере.
- Изменённое поведение покрыто тестами; все тесты и сборки проходят без ошибок и предупреждений, проверки не ослаблены.
- Новые схемы и макеты проверены после рендеринга: текст читается, элементы и связи не обрезаны.
- Версия обновлена по правилам `AGENTS.md`.
