# План: поддержка Pencil `.pen`

## Цель и границы

Добавить рендеринг документов Pencil (`.pen`, формат pen.dev) из fenced-блока Markdown. Блок преобразуется в безопасный inline SVG и работает в HTML, PDF, `--serve`, предпросмотре VS Code и `--check`.

В первой версии блок содержит один встроенный документ JSONC. Внешние файлы `.pen`, импорты, картинки, ссылки на Pencil и выполнение `script` не поддерживаются. Рендеринг работает локально и не обращается к сети.

Канонический язык блока — `pencil`; `pen` принимается как алиас:

````markdown
```pencil
{
  "version": "2.21",
  "children": [
    {
      "id": "profile",
      "type": "frame",
      "x": 0,
      "y": 0,
      "width": 320,
      "height": 240,
      "layout": "vertical",
      "gap": 12,
      "padding": 20,
      "fill": "#FFFFFF",
      "children": [
        {
          "id": "title",
          "type": "text",
          "content": "Профиль",
          "width": 280,
          "height": 36,
          "fontSize": 24,
          "fontWeight": "600",
          "fill": "#202124"
        },
        {
          "id": "save",
          "type": "rectangle",
          "width": 280,
          "height": 48,
          "cornerRadius": 8,
          "fill": "#315DEB"
        }
      ]
    }
  ]
}
```
````

`version`, `children`, `id` и `type` проверяются до рендеринга. Для совместимости фиксируется набор проверенных версий схемы; неизвестная версия даёт понятную ошибку. Формат Pencil — живой и может меняться, поэтому схема должна быть изолирована от SVG-рендера. См. [официальное описание `.pen`](https://docs.pencil.dev/for-developers/the-pen-format).

## Поддерживаемая подмножина

| Поддержать в первой версии | Явно отклонять с диагностикой |
|---|---|
| Контейнеры `frame` и `group` | `script`, `browser`, импорты и `ref`/переопределения компонентов |
| `rectangle`, `ellipse`, `polygon`, `path`, `text` | Внешние изображения, shader и mesh-gradient fills |
| Абсолютные координаты; layout `none`, `horizontal`, `vertical` с размерами, padding, gap и выравниванием | Темы и переменные `$name` |
| Однотонная заливка, обводка, opacity, rotation, скругление, clip у frame | Эффекты, blend modes и остальные неизвестные типы узлов |
| Текст: содержимое, семейство, размер, вес, стиль, выравнивание и перенос по ширине | Свойства, которые меняют вид и ещё не поддерживаются |

Поддерживаемая подмножина должна давать полезный статичный макет. Видимые неподдерживаемые свойства нельзя молча терять: ошибка называет ID узла и свойство. `enabled: false` не рендерится. Полный набор типов и свойства Pencil описаны в [TypeScript-схеме формата](https://docs.pencil.dev/for-developers/the-pen-format#typescript-schema).

## Поток обработки

~~~mermaid
flowchart LR
  MD[Markdown: pencil или pen fence] --> PL[remarkDiagramPlugin]
  PL --> JSONC[Разобрать JSONC и сохранить позиции ошибок]
  JSONC --> VALID[Проверить версию, дерево, типы и лимиты]
  VALID --> LAYOUT[Нормализовать координаты и простой layout]
  LAYOUT --> SVG[Создать статичный SVG]
  SVG --> SAFE[Общая проверка SVG и изоляция ID]
  SAFE --> INLINE[Встроить inline SVG]
  INLINE --> HTML[HTML и preview]
  INLINE --> PDF[PDF]
  PL --> CHECK[--check использует тот же renderer]
~~~

## Устройство в проекте

- Добавить `pencilRenderer` и зарегистрировать его в списке рендереров в обоих pipeline-функциях `compileMarkdown()` и `checkMarkdown()` в `src/compiler.ts`.
- Разделить код по ответственности: `pencil.ts` — адаптер `DiagramRenderer`; `pencil-json.ts` — разбор JSONC, версия и проверка дерева; `pencil-layout.ts` — вычисление простого layout и границ; `pencil-svg.ts` — SVG узлов и стилей. Держать каждый модуль в пределах принятого размера.
- Использовать `jsonc-parser` для комментариев Pencil и смещений parse-ошибок. Отключить trailing commas, если тестовый формат Pencil не требует их. Не исправлять повреждённый JSON автоматически. [Документация парсера](https://github.com/microsoft/node-jsonc-parser).
- Переносить строку и столбец ошибки из JSON в существующую диагностику Markdown. Лимиты первой версии: исходник до 1 MiB, до 10 000 узлов, глубина до 100 уровней; размер итогового SVG ограничить правилами существующих рендереров.
- Рендерить все поддержанные корневые элементы, включая отрицательные координаты. Вычислять SVG `viewBox` по границам рисунка, а порядок `children` сохранять как порядок слоёв.
- Экранировать текст и атрибуты SVG. Не создавать активный HTML, скрипты, внешние ссылки или сетевые ресурсы. Прогонять результат через `parseAndValidateSvg()` и `scopeSvgIds()` из общего pipeline.
- Ключ кэша должен включать версию рендерера и контракт схемы Pencil. Внешний кэш с TTL не нужен, так как источник встроен в Markdown.

## Проверки и документация

- Unit-тесты парсера: JSONC-комментарии, синтаксическая ошибка с позицией, обязательные поля, версия, неизвестный тип, дубли ID, неверные значения и лимиты.
- Unit-тесты layout и SVG: несколько корневых объектов, отрицательные координаты, вложенность, horizontal/vertical layout, фигуры, path, текст, заливки, обводки, rotation, clipping и порядок слоёв.
- Проверить понятный отказ для imports, refs, переменных, изображений, скриптов, shader и неизвестных видимых свойств. Проверить экранирование SVG и отсутствие вызовов сети.
- Интеграционные тесты компилятора: `pencil` и `pen`, SVG внутри HTML, `--check`, диагностика с исходным Markdown-файлом и строкой, два блока без конфликтов ID. PDF и preview используют тот же результат компилятора.
- Добавить `examples/blueprint-pencil.md` с рабочим статичным документом и ограничениями. Обновить README: синтаксис fence, подмножество, локальная обработка и диагностика неподдерживаемых функций.
- После тестов, сборки, typecheck, lint и форматирования поднять minor-версию `package.json`, так как это новая функциональность.

## Готовность

- `pencil` и `pen` блоки рендерятся локально в standalone HTML и PDF; `--serve`, VS Code preview и `--check` проходят через общий renderer.
- SVG не требует сети и проходит общую проверку безопасности проекта.
- Некорректный или неподдерживаемый документ не теряется без сообщения: диагностика указывает Markdown-блок и причину.
- Пример в `examples` и README описывают один и тот же контракт.
